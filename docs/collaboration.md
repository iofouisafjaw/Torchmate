# 通用协作任务（0.10.28）

协作计划复用现有执行模块：计划本身只保存目标、分工、修订号、子任务绑定、进度证据和事件记录，不直接扣料、放置、购买或调用作弊工具。当前有两个场景适配器，后续场景可使用相同的计划与验收接口。

## 使用

```
一起准备打克眼
药水我来
竞技场你来
继续协作
```

场地沿用三层×100格平台、两个篝火和两个心灯。协作场地预览不包含药水，以免同伴替玩家重复备料。药水是独立工作项：铁皮、再生、敏捷各2瓶，弱效治疗10瓶。每一项工作默认由同伴负责，玩家可在开始或途中交接。完成场地后再说「继续协作」，查看药水工作；玩家负责时将成品放入主背包，再说「核验协作」。

```
协作扩建2间NPC住房
备料你来
住房我来
继续协作
```

住房使用已有的1–3间木屋联排蓝图。备料调用原合成链，优先背包和可用附近箱子，不足时使用原有有限采集。备料后说「继续协作」选择施工位置。玩家负责施工时，预览确认施工被禁用；选址后游戏恢复运行，可以自行施工。完成后说「核验协作」，必须同时通过原位置的蓝图检查和每间房的原生入住检测。协作住房只填空，不拆自然地形或现有建筑；障碍需换位置或玩家自行处理。

通用操作：

| 指令 | 行为 |
|---|---|
| 协作计划／协作进度／现在做到哪了 | 查询分工和实际记录，不打断工作 |
| 药水我来／竞技场你来／备料我来／住房你来 | 停止旧执行、保留已完成部分，修改未完成项的责任人 |
| 住房改成三间 | 选址前重新计算1–3间住房，旧材料预览和确认作废 |
| 暂停协作／先停一下 | 停止旧执行，保留项目记录 |
| 继续协作 | 打开下一项或原位置的新预览；没有隐含批准 |
| 核验协作／我做完了 | 核实玩家负责项的真实库存或原位置现场；口头声明不是完成证据 |

选址后不允许用数量修改扩大原施工范围；需要另发协作扩建指令并选择新位置。场景内分工通过上述有界句式处理；混合目标、超限房间数及无法落实的附加要求会提示拆开说明，不宣称支持任意复杂协商。新项目先展示分工，不直接启动施工。

## 进度、恢复与权限

- 所有会消耗资源的工作仍由原模块签发预览ID、检查时限、库存／现场／制作站和玩家身份，并等待实际确认；分工、恢复及继续都不能代替确认。
- 进度来自 `CompanionTaskTracker` 的执行和验收结果。玩家施工与备料由适配器只读检查；最终完成前再次检查场地／住房和药水，不把已经消耗的历史备料当作最终物品。
- 失败继续使用原有 `TaskFailureReceipt`、实时资源查询、恢复请求预算和权限白名单。自动恢复生成的新子任务绑定回同一协作项；旧回调不能完成新修订，自动恢复沿用原预算。玩家手动继续会生成新的任务预览，仍需重新确认。
- 交接和手动继续复用原施工位置。住房中途缺料会重新打开备料项，只预算原蓝图尚未完成的格子；已放置部分不重复备料。未知副作用／执行异常不会因「继续协作」自动重试，要求人工检查后明确发起新任务。
- 同伴施工只有原模块验收才算完成；住房原生检测不合格也会形成失败回执，不能仅凭蓝图放置完成就报告成功。
- 拒绝或取消原模块预览会暂停协作；其他控制指令会暂停并撤销旧绑定。死亡、换世界、玩家对象或同伴对象替换会清理项目与旧任务。没有新增作弊授权、自动购买或跨世界续跑。
- 记录在本次进入世界的任务状态中；`collaboration_event` 写入现有执行日志供审计。退出世界清空运行状态，已建造内容由游戏保存；本版不提供跨会话任务恢复。

## 自动化与实机边界

`tests/CollaborationTests.cs` 覆盖通用状态、分工、修订、过期回调与有界意图解析；`tests/collaboration_adapter` 链接真实协作系统、任务跟踪器和失败恢复桥，用明确的假游戏接口测试两个场景的交接、验收、失败恢复和权限失效。原蓝图、合成链与竞技场执行器继续跑原有自动化测试。编译后的调用检查核对真实确认入口、原生住房检测、严格放置适配器与模块接线。

这些检查不等于真实游戏验收，也不是一次新的本地模型成功率评测。鼠标选址、暂停恢复、原生房屋检测、模组配方和实际合成／放置由玩家实机验收；本轮不启动游戏、不安装到个人 Mods、不更改存档。
